# Paper experiment section — data, tables, and how to regenerate them

Everything here is **generated from the experiment JSONs**: an earlier deck carried a sequential
headline of `47.7×` that silently included four instances whose output pins are tautologies, where
the real number is `36.5×`. The exclusions live in one place — `eval/artifact/paper_tables.py`,
which `eval/artifact/slide_tables.py` **imports** rather than restates, so the deck cannot drift
from the paper.

## Regenerate

```bash
R=$(PYTHONPATH=. python3 -m eval.paths results)
bash $R/paper/regenerate.sh      # checks data/MANIFEST.sha256, then: tables -> gate -> audit
                                 # -> figures -> copies RESULTS.md + tables.tex in here
```

which runs, over `$R/paper/data` (copies of the frozen rows):

```bash
eval/artifact/paper_tables.py --rivals $R/paper/data \
    --barbarik $R/paper/data/barbarik/circ_abc_*.jsonl \
    --out-md docs/paper/RESULTS.md --out-tex docs/paper/tables.tex
eval/artifact/verify_artifact.py --rivals $R/paper/data \
    --barbarik $R/paper/data/barbarik/circ_abc_*.jsonl          # the publishability gate
eval/rivals/check_emission_symmetry.py --results $R/paper/data --cycles 25
eval/eval_plots.py $R/paper/data --out-dir $R/paper/plots
```

The figures land in `$R/paper/plots/`, outside the repo like the data: per stage, Table 1's row
drawn (`vs_cmsgen_<stage>.png`) and Table 2's (`rivals_<stage>.png`), plus the two all-cells
scatters (`sps_scatter_cmsgen.png`, `sps_scatter_rivals.png`, hollow markers for T=50) that answer
what a geomean hides — how the instances are distributed around a ratio. Each classifies its cells
through the tables' own rules (`paper_tables.rival_cms_cells`, `rival_cells`), so it cannot draw a
cell its table excludes, and what is not drawn is named on it. `RESULTS.md`'s two commits differ:
the measured engine is the per-row build id (more than one value means mixed engines), `tables
generated at` only the HEAD the generator ran under.

The tables answer four questions: throughput against the SOTA uniform-ish CPU sampler (Table 1),
throughput against the gradient-descent GPU samplers on their metric (Table 2), whether the speedup
is the engine or the benchmark (Table 3), and the conditional-sampling uniformity certificate
(Table 4b). There is no Table 6 — no re-check arm has run against this engine, and an un-run check
is neither a pass nor a failure.

## The ten rules the generator enforces

Each, left implicit, produces a number a referee would reject; rules 1, 5 and 6 are three faces of
one principle — a cell that measures the instance rather than the sampler does not belong in a
geomean. Since 2026-09-07 every cell they remove, plus the both-zero and refused cases, shares ONE
printed column, `excluded`, itemised by name under each table.

1. **Vacuous pins leave the sequential geomeans**: `b02`, `b05`, `b07`, `s526` have constant
   last-cycle outputs at T=25, so every sampler scores ~100%.
2. **A ratio against a sampler that produced nothing is not a ratio**: CMSGen-zero cells count as
   outright wins and leave every geomean, which makes the figures conservative.
3. **The zero ledger is symmetric**: CMSGen-zero `inf`, GPAP-zero `0.0`, both-zero `None` — the
   last two falsy, so branching on `ratio` once showed 38 of their zeros as wins and hid all of
   ours. `inst = n + CMSGen=0 + GPAP=0 + excluded`, tested on the emitted LaTeX.
4. **Absent is not zero**: a row whose CMSGen arm never ran or whose subprocess crashed
   (`cms_error`) is screened per row and named; `verify_artifact.py` and `gpap bench --resume`
   refuse a stage mixing armed and armless rows.
5. **Zero-search cells are excluded**: EPFL `ctrl`, `dec`, `square`, `cavlc` emit at hundreds of M
   samples/s with no decisions and no implications — detected per row (`paper_tables.zero_search`)
   and continuously, `c432` at a rare pin having been an entire geomean at 89,786×.
6. **A space smaller than the sample request is enumerated, not sampled**:
   `paper_tables.tiny_space` (`2**support < 1000`, DEMOTIC's own carve-out for `c17`) applies to
   both tables and does not flatter us — it drops a 45,520× cell from Table 2 while *returning*
   1,348× → 1,620× to Table 1's combinational row.
7. **Every screen applies to every table**: `zero_search`, `tiny_space` and `VACUOUS_PINS` are
   shared by Tables 1 and 2, and both ledgers sum.
8. **A geomean over fewer than three instances is flagged, not quoted.**
9. **A GPAP/CMSGen ratio without its CPU is meaningless**: CMSGen is single-core, and this
   campaign's Xeon is 0.41× the reference laptop's CPU while GPAP moves 0.96× between the cards.
   `gpap bench` records `cpu` in every JSON.
10. **A tool that scored anything is scored, and a thin denominator is named, not screened**
    (2026-09-07, the user's rule; §17b): the 30-event floor is gone, cells under
    `THIN_DENOMINATOR = 30` on a side are named in the caveats with their count and ratio, and a
    row standing on one or two cells is flagged ‡ — quote the win count, not the ratio.

### The propagation table answers the obvious objection

Table 1's ratios span two orders of magnitude, which invites "you picked your benchmarks"; Table 3
answers with GPAP's near-constant implication rate against CMSGen's own `--statsevery` counters,
and `samples/s ratio = (implications/s ratio) / (implications-per-sample ratio)` closing on every
family row — quote those numbers from the generated tables, never from this file. The identity is
algebraic over one row set, so it fails only if the aggregation mixes row sets, which is the bug
`verify_artifact.py --rivals` uses it to catch (beside a physical band on the counters).

### Table 4b — what a Barbarik verdict does and does not say

Parameters are the CMSGen paper's own certification setting (ε=0.3, η=1.8, δ=0.1 ⇒ 1,872 samples
per instance), and eligibility is bucketed on the negative control's verdict (SPUR, exactly
uniform, must Accept), never on the screen's own estimate. The guarantee is asymmetric — a Reject
is unconditional, an Accept means *not caught*, never "proven uniform" — and "no verdict" bounds
coverage, not uniformity. Controls: `docs/findings/UNIFORMITY_FINDINGS.md`;
`eval/uniformity/barbarik_table.py` refuses to pool parameter settings.

## Comparability notes

GPAP is the 2026-09-01 core-sampler engine (RNG moved into libgpap): same-seed model *counts* are
not comparable across that boundary, *rates* are. `eval/artifact/make_artifact.sh` still speaks the
full-matrix layout and refuses mismatched arms, so until it learns this one the campaign directory
itself — `VERIFICATION.txt` and its own `README.md` inside — is the artifact of record.
