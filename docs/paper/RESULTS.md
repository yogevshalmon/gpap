The two protocols are DIFFERENT TASKS and must never be pooled: 'their pins' rows pin the 1–5 outputs the rival's own table names (rejection-easy by construction — p_accept is 0.03–0.5 there, printed per row), while miter/rare rows pin ALL outputs to a rare reachable pattern (p_accept ~1e-2–1e-6). Recurrent-CircuitSAT is scored on its own depth-POOLED unique count — solutions satisfying the target at ANY unroll depth start_point..T, a superset of the fixed-depth task every other row measures (the fixed-depth-only count is recorded per row as `unique_at_T`). The rival's batch is sized by a fixed 5 GiB autograd-graph budget (`pick_batch`); on easy instances their unique count saturates at that batch, so their score is bounded by a knob we set — generous timeouts (300 s vs our 60 s) and best-of-batch offset it, but state it. Constraint alignment is VERIFIED per row: miter mode asserts p(MITER=1) equals the instance's p_accept; native mode asserts bit-identical acceptance words between their index table on the original file and our reordered pins (`pin_check_ok`).
